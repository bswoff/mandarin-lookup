# Mandarin Learning App — Project Spec

## Overview

A personal browser-based Mandarin learning tool. Users look up Chinese words, get
rich LLM-generated detail about each word sense, and build a cached personal dictionary
over time.

**Stack:** React (frontend) + Rust (backend, HTTP API) + SQLite (local cache)  
**Runtime:** localhost only

---

## User Flow

1. User types a search query — either pinyin (e.g. `guo`) or a character (e.g. `過`)
2. A dropdown appears with matching sense candidates, each showing character + pinyin + short sense label (e.g. "to pass", "experience marker", "to celebrate")
3. User selects a candidate sense
4. App navigates to a dedicated word detail page at a clean URL (e.g. `/guo/to-celebrate`)

The detail page is preferred over a popup or inline expansion because:
- The content is substantial enough that a popup would feel cramped
- A clean URL enables bookmarking and linking
- "Similar words" navigation feels natural as page-to-page links

Pages are **definition-level, not word-level.** A word like 過 has many distinct
senses (to pass, experience marker, to celebrate, excessively) that each have their
own grammar patterns, common mistakes, and similar words. Each sense gets its own page.

---

## URL Schema

```
/word/{pinyin}/{slug}
```

- `pinyin` — the pinyin of the character without tone marks (e.g. `guo`)
- `slug` — derived deterministically from the sense label: take the first one or two
  words of the short sense label from the Tier 1 cache and slugify them
  (lowercase, spaces to hyphens). Examples:
  - "to pass" → `to-pass`
  - "experience marker" → `experience-marker`
  - "to celebrate" → `to-celebrate`
  - "excessively" → `excessively`

The slug is never generated by the LLM at detail-page time — it is always derived
from the already-stored Tier 1 sense label, ensuring stability and cache hit consistency.

---

## Caching — Two-Tier Architecture

### Tier 1 — Search Cache
**Populated:** on first search for a character or pinyin  
**Cache key:** the character (e.g. `過`)  
**Stores:** all sense candidates for that character — each row is `(character, pinyin, sense_label)`

When a user searches `guo` or `過`, the backend checks the Tier 1 cache first.
On a miss, it calls the LLM to enumerate all distinct senses, stores each as a row,
and returns them. On a hit, it returns the cached rows directly with no LLM call.

Searching by pinyin may match multiple characters (e.g. `guo` matches 過, 鍋, 國).
All matching characters are returned. Tier 1 rows are always stored and keyed by
character so pinyin lookups reuse the same rows.

### Tier 2 — Definition Cache
**Populated:** when a user first clicks through to a definition page  
**Cache key:** `(character, slug)` (e.g. `過`, `to-celebrate`)  
**Stores:** the full structured JSON for that word sense

On a Tier 2 miss, the backend calls the LLM with the character and sense label as
context, parses and validates the JSON response, stores it, and returns it.
On a hit, it returns the cached JSON directly.

### Cache Invalidation
Each definition page has a "Regenerate" button that:
1. Deletes the Tier 2 entry for `(character, slug)`
2. Re-calls the LLM
3. Stores and returns the fresh result

This is intentionally simple — no expiry, no bulk invalidation. Tier 1 entries
are considered stable and are not regenerated (sense lists for a character don't change).

## Word Detail Page

Each definition page displays the following sections, in order:

### 1. Character + Pinyin
- Full traditional character(s)
- Pinyin with tone marks (not numbers)

### 2. Definition
- The definition for this specific sense, clearly stated

### 3. Usage Summary
- A short paragraph on what the word conveys in this sense, its register
  (formal / colloquial / written / slang), and common contexts

### 4. Grammar Pairings
Displayed as a table:

| Pairing | Notes | Example sentence |
|---------|-------|-----------------|
| 介紹給   | Most common construction | 我來介紹給你認識。 |
| 介紹 (standalone) | Used in formal introductions | 請讓我介紹一下。 |

Each pairing gets exactly one example sentence so the grammar point is immediately concrete.

### 5. Example Sentences
- 3–5 sentences, chosen to cover the distinct ways this sense can be used
- Each sentence: Chinese characters → pinyin (with tones on every word) → English translation
- Number of sentences scales with how many distinct usages exist

### 6. Common Mistakes
- A short list of errors learners commonly make with this word sense
- Include incorrect example + correction where helpful

### 7. Similar Words
- 3–5 related words for this specific sense
- Each displayed as a link that navigates to that word's own detail page
- Include a one-line note distinguishing it from the current word

## Backend

### API Endpoints

**Search**
```
GET /api/search?q={query}
```
Checks Tier 1 cache first. On miss, calls LLM to enumerate senses, stores results,
returns list of candidates: `[{ character, pinyin, sense_label, slug }]`.

**Word detail**
```
GET /api/word/{character}/{slug}
```
Checks Tier 2 cache first. On miss, calls LLM with character + sense_label context,
stores result, returns full structured JSON.

**Regenerate**
```
POST /api/word/{character}/{slug}/regenerate
```
Deletes the Tier 2 cache entry and re-generates it. Returns the fresh JSON.

### SQLite Schema

```sql
-- Tier 1: sense candidates per character
CREATE TABLE senses (
  character   TEXT NOT NULL,
  pinyin      TEXT NOT NULL,
  sense_label TEXT NOT NULL,
  slug        TEXT NOT NULL,
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (character, slug)
);

-- Tier 2: full definition JSON per sense
CREATE TABLE definitions (
  character   TEXT NOT NULL,
  slug        TEXT NOT NULL,
  data        TEXT NOT NULL,  -- JSON blob
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (character, slug)
);
```

### LLM Integration
- Use the Anthropic API (`claude-sonnet-4-20250514`)
- Tier 1 prompt: given a character/pinyin, return a JSON array of all distinct senses,
  each with `pinyin`, `sense_label`, and `slug` (slug derived from first 1–2 words of sense_label)
- Tier 2 prompt: given a character and sense_label, return a JSON object covering all
  seven detail sections
- Parse and validate JSON before storing or returning
- All output should use Traditional Chinese characters throughout

## Frontend

### Pages / Routes
- `/` — Search home
- `/word/:pinyin/:slug` — Word detail page

### Search Component
- Single text input (pinyin or character)
- Dropdown of sense candidates appears as user types (debounced)
- Each candidate shows: character + pinyin + sense label
- Selecting a candidate navigates to its detail page

### Word Detail Component
- Renders all seven sections defined above
- Grammar pairings rendered as a table
- Similar words rendered as router links
- "Regenerate" button in the header area
- Pinyin uses proper tone mark characters (ā á ǎ à), not numbers
